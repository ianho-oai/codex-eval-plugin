# First round, then optional consistency rounds

Default to one iteration for every selected task × provider/model × supported effort. Preserve narrower user selections and any explicitly requested repeat count. The full default model/effort matrix still applies to both Codex and Claude Code; one iteration reduces initial spend, not coverage. Retries for transient rate limits remain part of an iteration, not extra consistency rounds.

After completing and reviewing the first round:

1. Present pass/fail, latency, token usage, known spend, missing costs, and remaining coverage. One sample cannot measure run-to-run consistency.
2. Offer **two additional iterations per configuration**, giving three observations total. Show the exact additional attempt count and a rough incremental cost estimate from first-round measured costs (roughly twice those costs for unchanged coverage). Explain missing telemetry, retries, and variable output/cache use; this is not a price guarantee. Offer a narrower matrix if the customer prefers.
3. Wait for explicit approval before any additional paid consistency runs. Declining or not responding means the completed first-round evaluation is the deliverable. Initial run approval and no spend stop do not authorize extra rounds. Repairs and provider retries use their separate agreed policies.
4. For approval covering the extra rounds, preserve the first run and prepare a separate customer-owned follow-up suite with identical tasks, graders, model/effort settings, CLI pins, pricing, environment, and concurrency, but `--repeats 2`. Validate and seal it, record approval, then execute into a fresh run directory. Do not change the old suite to three and resume it: repeats affect the seal, and a fresh three-repeat run would buy three additional iterations. Record which first-round run the follow-up extends. If other inputs changed, report it as a new comparison instead of pooling it.
5. Run the normal progress, reflection, report, and scoped dashboard flow. Include all configurations in the approved follow-up, not just failures or favorable models. Preserve failed attempts and missing telemetry.

The current dashboard averages within each run and does not automatically pool the first round with the two-repeat follow-up. Disclose this. A separately labeled three-observation summary may pool raw attempts only after verifying matching inputs above and retaining source run/attempt IDs. Compute each task/provider/model/effort mean from its three raw values (equivalently `(first + 2 * follow_up_mean) / 3` when complete), never an unweighted mean of two run means. Do not merge efforts or changed task revisions. Missing measurements keep that metric unavailable; show observed/expected counts and pass counts, and retain every original result. Three observations improve visibility into variability but are not statistical proof of reliability.
